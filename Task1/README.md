# Разработка проверочного листа по безопасности данных

## Классификация данных по ISO/IEC 27001 и 27002

### Публичные данные

**Примеры данных:**

- Витрина объектов недвижимости (базовый каталог)
- Актуальные данные о запланированных работах по ремонту (общая часть)
- Общая информация от управляющей компании

**Риски:**

| Риск | Описание (Обоснование)| Вероятность | Воздействие | Общая оценка | Меры по снижению риска |
|---|---|---|---|---|---|
| Искажение данных | Подмена цен или статуса квартиры на витрине из-за ошибки интеграции или атаки на API. Клиент бронирует по неверной цене, что ведёт к репутационным потерям. | Средняя | Высокое | Высокий | Внедрение проверки целостности контента (цифровые подписи витринных данных), строгий контроль CI/CD для фронтов и API-шлюзов. |
| Потеря данных | Удаление описаний объектов из CMS витрины из-за сбоя в гибридной среде тестирования, куда команды «могут использовать облачные ресурсы». Маркетинговая катастрофа «пустая витрина». | Низкая | Среднее | Низкий | Регламентное резервное копирование контента, разграничение доступов между продом и тестовыми средами облака. |
| Некачественные данные | Размещение на витрине устаревших планировок или неактуальных новостей ЖКУ. Снижается доверие к цифровым каналам. | Высокая | Низкое | Средний | Автоматическое снятие с публикации по триггеру, аудит контента перед стартом продаж новых очередей. |

### Внутренние данные

**Примеры данных:**

- Архитектурная модель и схемы потоков данных
- Данные финансового учёта
- Информация о структуре команд
- Планы по развитию BI/ML/AI-сервисов
- Статистика бронирований

**Риски:**

| Риск | Описание (Обоснование) | Вероятность | Воздействие	| Общая оценка | Меры по снижению риска | 
|---|---|---|---|---|---|
| Утечка данных | Публикация дорожной карты развития или диаграммы контейнеров вовне. Конкуренты используют архитектурные просчёты для атаки. | Средняя | Среднее | Средний | Внедрение Watermark в копии стратегических документов. DLP-фильтры на почтовых шлюзах для конфигурационных файлов. |
| Обесценивание данных | Некорректная обезличенная статистика бронирований из-за разрыва в координации точек регистрации. BI-отчёты врут, инвестиции в AI не окупаются. | Высокая | Высокое | Высокий | Построение единой шины данных (Data Bus) и Master Data Management (MDM) для клиентов перед запуском ML-сервисов. |
| Потеря данных | Удаление истории бухгалтерских проводок при миграции между частным и публичным облаком (гибридная инфраструктура, где «команды могут использовать облако для доработок»). Штрафы от ФНС. | Низкая | Критическое | Средний | Строгий запрет на хранение единственного экземпляра финансовых данных вне периметра ЦОД. Глубина бэкапа — до 5 лет. |

### Конфиденциальные данные

**Примеры данных:**

- Персональные данные клиентов (ФИО, телефон, почта, паспорт)
- Персональные данные собственников (платежи ЖКХ)
- Данные онлайн-сделок
- Данные партнёрских API
- Ключи шифрования и учётные данные к облачным ресурсам

**Риски:**

| Риск | Описание (Обоснование) | Вероятность | Воздействие | Общая оценка | Меры по снижению риска |
|---|---|---|---|---|---|
| Утечка данных (приоритет №1) | 1) API партнёров допускают доступ к данным чужих УК. <br/> 2) Инцидент «чужие ФИО в ЛК».  Прямое нарушение 152-ФЗ. | Критическая | Критическое | Критический | Жёсткий аудит API (OAuth 2.0 + MTLS), Row-Level Security на БД, немедленная изоляция данных тенантов. |
| Искажение данных | Подмена данных в расширенной форме сделки из-за атаки «man-in-the-middle» в гибридной сети между клиентом, PropDevelopment и госорганами. Срыв регистрации права собственности. | Средняя | Высокое | Высокий | Сквозное шифрование при интеграции с госорганами. Внедрение электронной подписи на уровне данных форм. |
| Потеря данных | Уничтожение/шифрование вирусами БД client-crm-app и client-mart-app. Нарушен контроль — компания не восстанавливает профили клиентов, невозможно провести сделку. | Средняя | Критическое | Критический | Строгая RPO (целевая точка восстановления) — не более 1 часа. Иммутабельные бэкапы, недоступные для изменения даже админам облака. |
| Некачественные данные | Дублирование карточек клиента в разных БД (витрина, CRM) без синхронизации. Как следствие — отправка уведомлений о сделке на неверный телефон. Жалобы клиентов. | Высокая | Высокое | Высокий | Дедубликация данных через MDM-систему, единый триггер верификации телефона и email. |


### Секретные данные

**Примеры данных:**

- Мастер-пароли и административный доступ к приватному облаку
- Резервные копии баз данных на глубину восстановления
- Критические уязвимости нулевого дня и результаты пентеста
- Журналы событий системы "Умный дом" (состояние запирающих устройств)

**Риски:**

| Риск | Описание (Обоснование) | Вероятность | Воздействие | Общая оценка | Меры по снижению риска |
|---|---|---|---|---|---|
| Утечка данных | Кража root-учеток частного облака через фишинг единственного ИБ-специалиста или DevOps-инженера. Получение полного контроля над всеми серверами недвижимости. | Высокая | Критическое | Критический | Внедрение PAM (Privileged Access Management), запрет личных учёток для администрирования, многокомпонентная аутентификация. |
| Потеря данных | Физический выход из строя СХД в ЦОД с повреждением резервных копий (без возможности восстановления критичных БД). Остановка всей деятельности. | Низкая | Критическое | Средний | Регулярное тестирование Disaster Recovery Plan. Геораспределённое резервирование критичных ключей шифрования. |
| Утечка / Обесценивание ключей | Компрометация ключей шифрования, которыми защищены бэкапы. Превращает все бэкапы в «цифровой мусор» (обесценивание) или инструмент для расшифровки злоумышленником (утечка). | Низкая | Критическое | Средний | Хранение ключей в HSM (Hardware Security Module), разделение секретов на несколько компонентов. |
| Искажение данных | Модификация сигналов «Умного дома». Ложная команда на открытие замка или шлагбаума. Прямая физическая опасность для жильцов. | Средняя | Критическое | Критический | Изоляция технологической сети IoT от корпоративной. Строгая аутентификация конечных устройств по сертификатам. |

### Примечания

Наибольшую угрозу для бизнеса представляют риски в категории Конфиденциальные данные (особенно утечка чужих данных через партнёрский API) и Секретные данные (компрометация системы «Умный дом» или PAM-доступов). Это прямо коррелирует с запросом топ-менеджмента предотвратить инцидент, аналогичный случившемуся у конкурента.
